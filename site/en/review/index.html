Review

A reviewer checks every contribution before it appears in the library. Reviewers are students who have taken the course and volunteer to help.

Who reviews

  • For now: the repository maintainer (@xeroz369), listed in .github/CODEOWNERS.
  • As more people join, each faculty or group of courses gets its own reviewers, also listed in CODEOWNERS by course folder. GitHub then requests the right reviewer on each pull request.
  • To review for a course you know well, open the Become a reviewer form.

The steps a contribution goes through

  1. Sent: an issue with the cần duyệt (needs review) label, or a pull request.
  2. Automatic checks: CI checks the format, file types, sizes and duplicates, and scans for student IDs, emails and phone numbers.
  3. A reviewer reads it using the checklist below and asks the sender questions in the issue when needed.
  4. Published: for form submissions, the reviewer opens a pull request, uploads the file to a GitHub release, records url and sha256, and merges.
  5. The issue is closed with a link to the course page.

Target: a reply to every contribution within seven days. Takedown requests come first; see Takedown.

Reviewer checklist

  • It really is the sender's own work: not lecturer slides, exams or answer keys, and not copied from another site. If in doubt, ask for the source.
  • No personal information is left: open every page and check photos, headers, footers and file properties (Author in .docx and .pdf).
  • Graded work: the submission and grading deadlines have passed, gradedAfter is set, and it is labelled as a reference.
  • License: CC BY-SA 4.0 (or CC BY 4.0, CC0) for the sender's own work; for links, the source's actual license.
  • Right course, right type, a clear title, no advertising.
  • For .zip files: open them and check that there are no executables.
