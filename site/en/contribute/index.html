Contribute material

The library works because students send material and review each other's work. You don't need Git: fill in a form on GitHub and attach your file.

What you can post

  • Material you wrote yourself: summaries, notes, cheat sheets, solutions you worked out, prelab templates (report outline and preparation questions, without graded data).
  • Quiz packs in the BK Study Desk Study Pack v1 format.
  • Links to public, legal resources: open textbooks (OpenStax, MIT OpenCourseWare, and others), public videos, faculty pages.
  • Prelab or report references, only after the submission and grading deadlines have passed, clearly labelled as references.

What you can't post

  • Slides, textbooks, exam papers or answer keys from lecturers or the university without written permission.
  • Files copied from Scribd, Studocu, Course Hero or similar sites.
  • Work that shows a student ID, name, signature, email, phone number or a face (yours or anyone else's).
  • Work that is still open for submission or grading.
  • Executable files (.exe, .bat, and so on) and files over 20 MB.

Option 1: send a form, no Git needed

  1. Sign in to GitHub (create a free account if you don't have one).
  2. Open the Contribute material form, or select Send material on a course page so the course code is filled in for you.
  3. Enter the course code, type, title and term, and select the three checkboxes (you wrote it, you agree to CC BY-SA 4.0, you removed personal information).
  4. Drag your file into the Attachments box. GitHub accepts attachments up to 25 MB for documents and .zip files and 10 MB for images; the library accepts up to 20 MB. Zip KiCad projects and multiple files into one .zip.
  5. Submit. A reviewer replies in the issue.

Only have a link? Use the Add a link form.

Option 2: pull request (if you use Git)

  1. Fork the repository and add courses/<ID>/items/<id>.json. Small .md files (under 1 MB) go in courses/<ID>/files/. PDF, .docx, image and .zip files don't go into Git; a reviewer uploads them to a GitHub release.
  2. Run npm test and npm run build, then commit the generated files too.
  3. Open a pull request and complete the checklist.

All fields are described in CONTRIBUTING.md.

After you send it

At least one reviewer checks every contribution before it appears in the library. See how reviewing works. To have something removed, see Takedown.
