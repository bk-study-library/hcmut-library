Review

A reviewer checks every contribution before it appears in the library. Reviewers are students who have taken the course and volunteer to help.

Who reviews

  • For now: the repository maintainer (@xeroz369), listed in .github/CODEOWNERS.
  • As more people join, each faculty or group of courses gets its own reviewers, also listed in CODEOWNERS by course folder. GitHub then requests the right reviewer on each pull request.
  • To review for a course you know well, open the Become a reviewer form.

The steps a contribution goes through

  1. Sent: through the upload page (a bot opens a pull request), through the Add a link form (an issue with the cần duyệt label; the reviewer opens the pull request from the issue by hand), or as your own pull request.
  2. Automatic checks: for files sent through the web page, the kiem-file workflow scans for viruses, strips PDF metadata, warns about student IDs, emails and phone numbers, and writes the release link into the pull request. The validate CI checks format, file types, sizes and duplicates.
  3. A reviewer reads it using the checklist below and asks the sender questions in the pull request or issue when needed.
  4. Merged: the reviewer merges the pull request. The phat-hanh-file workflow publishes the file to the files-HKxxx GitHub pre-release. If the pull request is closed instead, don-kho cleans up the waiting file.
  5. The issue is closed (for links) with a link to the course page.

Target: a reply to every contribution within seven days. Takedown requests come first; see Takedown.

Reviewer checklist

  • It is not a copyrighted book file. Books become the Sách tham khảo type, listed by title only.
  • Personal information: read the machine warning in the PR and decide. It only warns, it does not block.
  • License: CC BY-SA 4.0 (or CC BY 4.0, CC0) for the sender's own work; for links, the source's actual license.
  • Right course, right type, a clear title, no advertising.
  • For .zip files: open them and check that there are no executables.
